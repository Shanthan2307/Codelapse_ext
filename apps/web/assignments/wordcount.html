1. Overview

Which words does a piece of text use most? You will write a small program that tidies up each word, counts how often every word appears, and lists the most common ones. Counting things by name is one of the most common jobs in programming, and the tool for it in Python is the dictionary.

You will write it in VS Code while the CodeLapse extension records how you work. When you submit, you will answer four short questions about your own work and your own code.

What you will practise

  • Dictionaries: adding a key, updating its value, and handling a key you have not seen yet.
  • String methods: split, strip and lower.
  • Sorting with a key, and breaking ties in a fixed order.
  • Tuples and lists of tuples.

2. What to build

Write everything in one file, wordcount.py. No imports are needed.

def clean_word(word: str) -> str

  • Removes these punctuation characters from both ends of the word: . , ! ? ; : " ' ( ) - and returns it in lower case.
  • Punctuation inside a word stays ("don't" stays "don't"). A word made only of punctuation becomes "".

def count_words(text: str) -> dict[str, int]

  • Splits text on whitespace, cleans each piece with clean_word, skips empty results, and returns a dictionary from each word to how many times it appears.
  • "Go go GO!" is one word appearing 3 times.

def top_words(counts: dict[str, int], n: int) -> list[tuple[str, int]]

  • Returns the n most frequent words as (word, count) tuples, most frequent first.
  • Words with the same count are in alphabetical order. If there are fewer than n words, return them all; if n is 0, return [].
  • Must not change the counts dictionary.

Running it as a program

  • Under if __name__ == "__main__":, put a short text in a variable, count its words, and print the top 3 as word: count.
Not allowed collections.Counter, re (regular expressions), or any other import. Allowed: dictionaries and their methods (get, items, in), string methods, sorted() with key=, slicing a list, and lambdas.

5. Hints

Read one hint at a time and try it yourself before moving on to the next.

  1. Splitting
    text.split() with no argument splits on any run of spaces, tabs and new lines, and never gives empty pieces. text.split(" ") behaves differently: try both on "a b".
  2. Stripping
    word.strip(chars) removes any of the characters in chars from both ends, as many as there are, and leaves the middle alone. Check how to put both kinds of quote mark into one string.
  3. A key you haven't seen
    counts[word] += 1 fails with KeyError the first time a word appears. Either check if word in counts first, or use counts.get(word, 0), which gives a default when the key is missing.
  4. Sorting pairs
    counts.items() gives (word, count) pairs. sorted(..., key=...) sorts by whatever the key function returns for each pair. If the key returns a tuple, Python compares the first parts, and only looks at the second part when the first parts are equal.
  5. Biggest first, but A before Z
    You want counts in descending order and words in ascending order at the same time. reverse=True flips both. Think about a key that makes a bigger count sort earlier on its own.
  6. Taking the first n
    A slice like items[:n] never fails, even when n is larger than the list.

7. Common mistakes

MistakeWhat happens, and the fix
counts[word] += 1 on a new wordKeyError. Give missing words a starting value first.
Forgetting to lower-case"The" and "the" are counted as different words.
Counting the empty word"--" adds a "" key. Skip empty results.
reverse=True with a (count, word) keyTies come out Z to A. Sort descending by count and ascending by word.
Using .replace to remove punctuationIt also removes the apostrophe inside "don't". Only the ends are cleaned.
Sorting counts in place, or deleting from itThe caller's dictionary changes. sorted() makes a new list.

9. The four questions

Right after you submit, the page shows four short questions about your own work: two about things you did while working (for example an error you fixed, or something you rewrote), and two about specific lines of your code. Every student gets different questions.

  • You have one hour from submitting to answer, and you can submit your answers once. A timer shows the time left; your draft is kept if you refresh the page.
  • Write a few sentences each, in your own words. Spelling and grammar do not matter.
  • Explain why, not just what: why your sort key orders the words the way it does, why you chose that approach, what an error message told you.
  • Be specific: mention the actual line, variable, error or change. "It works" says much less than "this check comes first because …".
  • If you are not sure, say what you think and why. An honest partial answer is better than a vague one.
