1. Overview

A teacher has a list of test scores and wants a few numbers about them: the average, the highest score, how many students passed, and a letter grade for each score. You will write four small functions that work these out. Python has built-in shortcuts for some of this (sum, max), but here you write the loops yourself, so you practise the patterns those shortcuts hide.

You will write it in VS Code while the CodeLapse extension records how you work. When you submit, you will answer four short questions about your own work and your own code.

What you will practise

  • Lists and looping over them with for.
  • The accumulator pattern: a variable that starts at a value and is updated on every pass (a running total, a count, the best so far).
  • Conditions with if / elif / else, and getting the boundaries right (is 90 an A or a B?).
  • Handling the empty list, None as "no answer", and a parameter with a default value.

2. What to build

Write everything in one file, grades.py. Scores are whole numbers from 0 to 100. No imports are needed.

def average(scores: list[int]) -> float

  • Returns the mean of the scores: their total divided by how many there are.
  • For an empty list it returns 0.0 (and must not crash with a division by zero).

def highest(scores: list[int]) -> int | None

  • Returns the largest score. For an empty list it returns None.
  • Must work when every score is 0 (the answer is then 0, not None).

def letter_grade(score: int) -> str

  • Returns "A" for 90 and above, "B" for 80–89, "C" for 70–79, "D" for 60–69 and "F" below 60.

def count_passing(scores: list[int], pass_mark: int = 60) -> int

  • Returns how many scores are at or above pass_mark. When the caller leaves pass_mark out, it is 60.

Running it as a program

  • Under if __name__ == "__main__":, make a list of scores (for example [72, 95, 88, 61, 45]), and print the average (rounded to 2 decimals), the highest score, the number passing, and each score with its letter grade.
Not allowed sum(), max(), min(), sorted(), .sort(), statistics or any other import. Allowed: for and while loops, len(), if/elif/else, round() for printing, and ordinary arithmetic.

4. A plan that works

  1. Create the folder, open it in VS Code and start CodeLapse (section 8). Create grades.py.
  2. Write the if __name__ == "__main__": block so it only prints the list. Run it, so you know your setup works.
  3. Write average, print its result and run. Then try it on [].
  4. Write highest and check it against the table, including [0, 0, 0].
  5. Write letter_grade and try every boundary in the second table.
  6. Write count_passing; call it once without pass_mark and once with pass_mark=70.
  7. Add a few assert checks (section 6), run once more, and save.

5. Hints

Read one hint at a time and try it yourself before moving on to the next.

  1. The accumulator
    Make a variable before the loop (for example a total that starts at 0), and update it inside the loop for every score. After the loop it holds the answer.
  2. The empty list
    Dividing by len(scores) fails when the list is empty. Check for that case first and return early.
  3. The best so far
    For highest, keep "the best score seen so far". The tricky part is what it should start as. Starting at 0 works for these scores but hides the empty-list case; starting at None means "nothing seen yet". Then think about how to test for None so that a real score of 0 is not mistaken for it.
  4. Order of the conditions
    An if/elif chain stops at the first true condition. If you check the lowest grade first, or the highest first, the other conditions change. Pick one order and test 89, 90 and 59 by hand.
  5. Default parameters
    Writing pass_mark: int = 60 in the def line means callers may leave it out. Inside the function, use pass_mark, never the number 60.
  6. Return, don't print
    The four functions return their results; only the __main__ block prints.

6. Test your program

  • Run python3 grades.py in the VS Code terminal after every change (on Windows py grades.py).
  • Let Python check for you with assert lines in the __main__ block:
assert average([]) == 0.0
assert highest([0, 0, 0]) == 0
assert letter_grade(90) == "A"
assert count_passing([59, 60, 61], pass_mark=70) == 0

Self-check before you submit

  • Runs with python3 grades.py without errors.
  • No sum, max, min, sorted or imports.
  • average([]) is 0.0 and highest([]) is None.
  • Every boundary in the letter-grade table gives the right letter.
  • count_passing counts a score equal to the pass mark, and uses pass_mark when it is given.
  • You can explain, in your own words, what each accumulator starts as and why.

9. The four questions

Right after you submit, the page shows four short questions about your own work: two about things you did while working (for example an error you fixed, or something you rewrote), and two about specific lines of your code. Every student gets different questions.

  • You have one hour from submitting to answer, and you can submit your answers once. A timer shows the time left; your draft is kept if you refresh the page.
  • Write a few sentences each, in your own words. Spelling and grammar do not matter.
  • Explain why, not just what: why an accumulator starts where it does, why you chose that approach, what an error message told you.
  • Be specific: mention the actual line, variable, error or change. "It works" says much less than "this check comes first because …".
  • If you are not sure, say what you think and why. An honest partial answer is better than a vague one.

10. Working honestly, and what is recorded

Write the code yourself, and please turn off AI coding assistants (such as GitHub Copilot) for this assignment. Mistakes, errors and rewrites are completely normal; they are part of how programs get written.

CodeLapse records only the folder you choose: what you type, when you switch files, and the programs you run in the VS Code terminal with their output. It does not record other folders, websites, other apps or your file paths and username. Nothing leaves your computer until you export and upload it yourself.

Your instructor sees your code, your answers, a summary of your recording (how long you worked, how much was typed or added in larger pieces such as pastes, how your runs went), and a short review of how well your answers explain your code. None of this is a grade or an accusation: it describes how the work happened, and your instructor decides what it means. If you are unsure whether something is allowed, ask your instructor.
