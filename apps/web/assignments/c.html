1. Overview

You will write a small C program with two functions: one that reverses a string in place, and one that counts its vowels. It is a short program, but it touches several ideas that matter in every C program you will write: how strings are stored, how loops move through an array, and what it means for a function to change the data it is given.

You will write it in VS Code while the CodeLapse extension records how you work. When you submit, you will answer four short questions about your own work and your own code.

What you will practise

  • How C stores a string: an array of char that ends with the null character '\0'.
  • Using strlen and loops with indices (or pointers) to walk through an array.
  • Changing data in place through a pointer, and protecting data you only read with const.
  • Testing your own code on ordinary and unusual inputs, and fixing compiler errors and warnings.

2. What to build

Write everything in one file, reverse.c. Use only the C standard library (for example <stdio.h>, <string.h>, <ctype.h>).

void reverse(char *s)

  • Reverses the string s in place: after the call, the same array holds the characters in reverse order.
  • Must not use a second array or string, and must not allocate memory (malloc). A single char variable for swapping is fine.
  • Must work for any string, including the empty string "" and a string of one character.
  • Returns nothing: the change happens to the caller's array.

int count_vowels(const char *s)

  • Returns how many vowels the string contains. The vowels are a e i o u, in either case (A E I O U count too).
  • y is not a vowel for this assignment. Spaces, digits and punctuation are not vowels.
  • Must not change the string. The const in the parameter is part of the required signature.

int main(void)

  • Puts a test word in a char array (for example "codelapse"), calls both functions on it, and prints the reversed word and the vowel count.
  • Returns 0.
Not allowed A second array or buffer to build the reversed string; malloc; any non-standard library; library functions that reverse for you (some systems have strrev, which is not standard C). The program must compile with no warnings using gcc -Wall.

5. Hints

Read one hint at a time and try it yourself before moving on to the next. They start general and get more specific.

  1. Getting started
    A C string is an array of char followed by '\0'. strlen(s) (from <string.h>) gives the number of characters before the '\0', so the last real character is at index strlen(s) - 1. Never move the '\0'.
  2. The idea
    Picture two fingers, one on the first character and one on the last. Swap what they point at, then move both fingers one step towards the middle. Repeat.
  3. When to stop
    Stop when the fingers meet or cross: that is after about half the length. If you keep going to the end, every pair is swapped a second time and the string comes back unchanged. With an odd length the middle character never needs to move. Check your stopping rule against "ab" and "abc".
  4. Swapping
    To swap two characters you need somewhere to keep one of them for a moment: one temporary char. If you write s[i] = s[j]; s[j] = s[i]; without it, both end up the same.
  5. Indices or pointers
    You can use two int or size_t indices, or two char * pointers. Both are fine; be ready to explain your choice. Careful with the empty string: strlen returns size_t, which cannot be negative, so strlen(s) - 1 on "" is a huge number, not -1. Make sure your loop does not run at all for "".
  6. Counting vowels
    Walk through the string until you reach '\0' and check each character. For upper case, either compare against both cases or turn the character into lower case first with tolower from <ctype.h> (cast the argument to unsigned char). If you look characters up in a string of vowels with strchr, remember that strchr also "finds" the '\0' at the end, so only call it on real characters.
  7. const
    const char *s promises that count_vowels only reads the string. If you try to change a character through s, the compiler reports an error. That is the point.
  8. main
    Write char word[] = "codelapse";, not char *word = "codelapse";. The first makes an array you are allowed to change; the second points at a string literal, and changing it is undefined behaviour (often a crash). Because reverse changes word itself, print the original before you reverse it.

6. Test your program

  • Build with gcc -Wall -o reverse reverse.c after every change, in the VS Code terminal. Read warnings as carefully as errors.
  • Run ./reverse and compare with the table. Change the test word in main to try the edge cases, or call your functions on several words and print each result.
  • A quick way to check yourself: printf("%s %d\n", word, count_vowels(word)); after each step.

Self-check before you submit

  • Compiles with gcc -Wall with no errors and no warnings.
  • reverse uses no second array and no malloc.
  • Correct for "", "a", "ab", "abc" and "Hello, World!".
  • count_vowels counts capital vowels and does not count y.
  • The function signatures are exactly void reverse(char *s) and int count_vowels(const char *s).
  • main prints the reversed word and the vowel count, and returns 0.
  • You can explain, in your own words, why your loop stops where it does.

7. Common mistakes

MistakeWhat happens, and the fix
Looping all the way to the endEvery pair is swapped twice and the string looks unchanged. Stop at the middle.
Off by one at the endUsing s[len] as the last character swaps the '\0' to the front, and the string looks empty. The last character is s[len - 1].
Swapping without a temporaryBoth positions end up with the same character.
Changing a string literalchar *w = "hello"; reverse(w); may crash. Use char w[] = "hello";.
Forgetting a semicolon or a bracketThe compiler often reports it on the line after the mistake. Look at the line above too.
Forgetting capital vowels, or counting y"AEIOU aeiou" must give 10 and "rhythm" must give 0.
Printing the "original" after reversingThe array has already changed, so both lines show the reversed word.
Ignoring warningsWarnings from -Wall often point at real problems, such as an unused variable. Calling strlen without #include <string.h> gives a warning or an error, depending on the compiler.

9. The four questions

Right after you submit, the page shows four short questions about your own work: two about things you did while working (for example a build that failed and how you fixed it, or something you rewrote), and two about specific lines of your code. Every student gets different questions.

  • You have one hour from submitting to answer, and you can submit your answers once. A timer shows the time left; your draft is kept if you refresh the page.
  • Write a few sentences each, in your own words. Spelling and grammar do not matter.
  • Explain why, not just what: why the loop stops there, why you chose that approach, what the compiler error told you.
  • Be specific: mention the actual line, variable, error or change. "It works" says much less than "it stops at half the length because …".
  • If you are not sure, say what you think and why. An honest partial answer is better than a vague one.

10. Working honestly, and what is recorded

Write the code yourself, and please turn off AI coding assistants (such as GitHub Copilot) for this assignment. Mistakes, failed builds and rewrites are completely normal; they are part of how programs get written.

CodeLapse records only the folder you choose: what you type, when you switch files, and your builds with their output. It does not record other folders, websites, other apps or your file paths and username. Nothing leaves your computer until you export and upload it yourself.

Your instructor sees your code, your answers, a summary of your recording (how long you worked, how much was typed or added in larger pieces such as pastes, how your builds went), and a short review of how well your answers explain your code. None of this is a grade or an accusation: it describes how the work happened, and your instructor decides what it means. If you are unsure whether something is allowed, ask your instructor.
