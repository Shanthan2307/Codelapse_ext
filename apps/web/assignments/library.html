1. Overview

A small library lends books to its members. You will build it in two parts, the way real programs are built. First a module, library.py, that knows the rules: which books exist, how many copies are on the shelf, and who may borrow what. Then a program, main.py, that imports the module and uses it to process a list of commands such as checkout 111 ana, printing what happened.

The module never prints and never reads input: it only keeps the data and enforces the rules, and it reports a broken rule by raising an exception. The program decides what to show the user. Keeping those two jobs apart is the main idea of this assignment.

You will write it in VS Code while the CodeLapse extension records how you work. When you submit, you will answer four short questions about your own work and your own code.

What you will practise

  • Writing a module and importing it from another file (from library import ...).
  • Classes and objects: __init__, attributes, methods, and objects that hold other objects.
  • Exceptions: defining your own (class LibraryError(Exception)), raising it, and catching it with try / except in another file.
  • Keeping state consistent: copies on the shelf, who has which book, a limit per member.
  • Parsing simple text commands.

2. What to build

Put both files in the same folder. Use only plain Python; the only import allowed is main.py importing your own library.

Part A: library.py (the module)

MAX_LOANS = 3 and class LibraryError(Exception)

  • A constant for how many books one member may hold at once, and your own exception type. Every broken rule raises LibraryError with a short message.

class Book

  • Book(isbn: str, title: str, author: str, copies: int) stores all four. If copies is less than 1, it raises ValueError.
  • It also keeps track of who currently has a copy (one entry per member who borrowed it).
  • available() -> int: how many copies are on the shelf right now.

class Library

  • Library() starts empty.
  • add_book(book): adds a book. Raises LibraryError if a book with the same ISBN is already there.
  • available(isbn) -> int: copies on the shelf. Raises LibraryError for an unknown ISBN.
  • checkout(isbn, member): lends one copy to member. Raises LibraryError, checking in this order:
    1. the ISBN is unknown;
    2. the member already has a copy of this book;
    3. no copies are on the shelf;
    4. the member already has MAX_LOANS books.
    When it raises, nothing changes.
  • return_book(isbn, member): takes the copy back. Raises LibraryError if the ISBN is unknown or the member doesn't have this book.
  • loans_of(member) -> list[str]: the titles the member has, in alphabetical order ([] if none).
  • The module does nothing when imported: no prints, no test code at the top level (put any experiments under if __name__ == "__main__":).

Part B: main.py (the program)

def run(commands: list[str], library: Library) -> list[str]

  • Imports what it needs from library. Goes through the commands in order and returns one output line per command (blank commands are skipped and give no line).
  • The commands, with words separated by spaces:
    CommandOutput line when it works
    checkout ISBN MEMBERok: MEMBER borrowed ISBN
    return ISBN MEMBERok: MEMBER returned ISBN
    available ISBNISBN: N available
    loans MEMBERMEMBER: Title, Title or MEMBER: no books
  • When the module raises LibraryError, the line is error: followed by its message, and the program carries on with the next command.
  • Anything else (an unknown word, or the wrong number of words) gives error: unknown command: followed by the command.

Running it as a program

  • Under if __name__ == "__main__": in main.py, build the sample library below, run the sample commands, and print each output line. Run it with python3 main.py.
Rules All the rules live in library.py; main.py must not check copies or limits itself, and library.py must not print. Do not reach into the library's attributes from main.py: use its methods. No imports other than your own module.

5. Hints

Read one hint at a time and try it yourself before moving on to the next.

  1. Importing
    from library import Book, Library, LibraryError works when library.py is in the same folder as the file you run. If Python says ModuleNotFoundError, check the terminal is in that folder and the file name is exactly library.py.
  2. Where to keep the books
    The library needs to find a book by its ISBN quickly. Think about which built-in type maps one value (an ISBN) to another (a Book).
  3. Who has a copy
    If each Book remembers which members currently have it, then available() is the number of copies minus the number of borrowers, and "already has this book" is a membership test. Then think about how to count how many books one member has across all books.
  4. Raise, don't print
    raise LibraryError(f"no copies of {book.title} are available") stops the method immediately. Do all checks before changing anything, so a refused checkout leaves the library exactly as it was.
  5. Catching in the other file
    In run, put the work for one command inside try:. In except LibraryError as e:, str(e) (or f"{e}") is the message you raised. The loop continues with the next command after the except block.
  6. Parsing a command
    line.split() gives a list of words. Check the first word and the number of words before using parts[1] or parts[2], or a short command will raise IndexError.
  7. An import that does nothing
    Any code at the top level of library.py runs on import. If you tested it with prints there, move them under if __name__ == "__main__":.

6. Test your program

  • Run python3 main.py in the VS Code terminal after every change (on Windows py main.py).
  • Check the module on its own, too. Running python3 -c "import library" must print nothing.
  • Let Python check for you with assert lines in main.py's __main__ block:
lib = sample_library()          # however you build the sample
assert run(["checkout 111 ana", "available 111"], lib) == ["ok: ana borrowed 111", "111: 1 available"]
assert run(["loans bob"], lib) == ["bob: no books"]
assert run(["checkout 111"], lib) == ["error: unknown command: checkout 111"]

Self-check before you submit

  • python3 main.py prints the 16 lines of the example, in order.
  • library.py never prints, and importing it prints nothing.
  • main.py imports from library and never checks a rule itself.
  • The four checkout rules are checked in the given order, and a refused checkout changes nothing.
  • An error doesn't stop the run: the next command still happens.
  • You can explain, in your own words, why the rules are in library.py and the printing is in main.py.

7. Common mistakes

MistakeWhat happens, and the fix
Printing an error inside library.pyThe program can't decide what to show, and run returns the wrong lines. Raise LibraryError instead.
Changing state before all checks passA refused checkout still uses up a copy. Check first, change last.
Checking the rules in another ordercheckout 111 ana above says "no copies" instead of "already has Dune".
except Exception or a bare except:Real bugs (a typo, an IndexError) are hidden as if they were library errors. Catch LibraryError.
Storing the borrowers list as a class attributeEvery book shares one list. Create it in __init__ with self..
Test code at the top of library.pyIt runs every time main.py imports the module.
parts[2] without checking the lengthIndexError on checkout 111. Count the words first.

9. The four questions

Right after you submit, the page shows four short questions about your own work: two about things you did while working (for example an error you fixed, or something you rewrote), and two about specific lines of your code. Every student gets different questions.

  • You have one hour from submitting to answer, and you can submit your answers once. A timer shows the time left; your draft is kept if you refresh the page.
  • Write a few sentences each, in your own words. Spelling and grammar do not matter.
  • Explain why, not just what: why a rule lives in the module and not in the program, why you chose that approach, what an error message told you.
  • Be specific: mention the actual line, variable, error or change. "It works" says much less than "this check comes first because …".
  • If you are not sure, say what you think and why. An honest partial answer is better than a vague one.

10. Working honestly, and what is recorded

Write the code yourself, and please turn off AI coding assistants (such as GitHub Copilot) for this assignment. Mistakes, errors and rewrites are completely normal; they are part of how programs get written.

CodeLapse records only the folder you choose: what you type, when you switch files, and the programs you run in the VS Code terminal with their output. It does not record other folders, websites, other apps or your file paths and username. Nothing leaves your computer until you export and upload it yourself.

Your instructor sees your code, your answers, a summary of your recording (how long you worked, how much was typed or added in larger pieces such as pastes, how your runs went), and a short review of how well your answers explain your code. None of this is a grade or an accusation: it describes how the work happened, and your instructor decides what it means. If you are unsure whether something is allowed, ask your instructor.
